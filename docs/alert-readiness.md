# Private, fixed-purpose alert readiness

`GET /api/ops/alert-readiness` is a machine-readable **no-send** diagnostic. It is disabled without a separate `ALERT_READINESS_READ_SECRET` of at least 32 characters. This capability does not change or expose the existing scheduler or delivery credentials.

The route accepts only GET with the exact Bearer read credential and **no query controls**. It cannot accept a recipient, test send, baseline, live mode or scheduler marker. After read authorization it invokes the canonical delivery function with a server-owned in-memory authorization Request and hardcoded `dryRun: true, queueMode: "off"`. This is not a network call to the live delivery route. It never invokes the mixed delivery/billing-maintenance route and must never update the real cron heartbeat.

The response is an explicit allowlist of aggregate readiness counters and configuration booleans. Raw exceptions, user IDs, addresses, phone numbers and metadata are excluded. Responses are private/no-store. Missing/invalid read credentials return 401; query controls return 400; malformed or unexpectedly live diagnostic results return a sanitized 503.

`summary.queueMode` is the **diagnostic execution mode**, deliberately off—not the configured production queue mode. Would-send counts are eligibility observations, not successful queue claims or promised sends. The diagnostic maps the canonical dry-run's simulated `onSiteAlertsCreated` count to `onSiteAlertsWouldCreate` and reports `onSiteAlertsCreated: 0`; it does not change the legacy delivery response. Nonzero email, SMS or push sent counters still fail closed. A current source snapshot, matched member, provider acceptance and handset receipt remain separate evidence layers. `deviceReceiptProven` is always false here. Use the public ops health contract and durable delivery records to verify the actual scheduler and delivery execution.

Provision a unique random read key through the established Vercel release path, keep its local copy machine-protected, and never reuse or rotate `CRON_SECRET` merely for diagnostics. Verify the deployed exact custom-domain route with redirects disabled, wrong/absent credentials rejected, a valid read returning fresh source evidence, and a `dryRun=0` query rejected. Keep the existing no-write dry-run regression tests mandatory whenever the canonical delivery function changes. No user-facing feedback prompts, surveys, or new member interactions are introduced.

## Read-only capture path

`scripts/capture-coverage-premises-baseline.mts` reuses the application's verified `createRemoteSiteSnapshotReader` and read-only `VercelBlobSnapshotStorage`. It reads the active pointer once, requires public health to identify the exact operator-supplied 40-character production commit and that same active snapshot, and pins that pointer for every export read. It rechecks both pointer hash and live release/snapshot at the end. HTTP 200 or 503 health JSON is accepted only when the release itself is healthy and identities match; degraded engine status must not hide stale premises.

Only `drops`, `stores`, `locations` and `state-health` can be decrypted through the wrapper. The existing reader verifies the manifest identity/hash and each decrypted payload's declared size/hash. Active-export failure, malformed schema, pointer movement or live identity mismatch fails the capture without exporting a partial baseline. A historical failure is an explicit gap; its partial rows are discarded.

The sole output, `out/coverage-premises-baseline.json`, contains public premise address/name/state/city/postcode, store/source identifiers and source hostname, observation layer, current/stale flags, origins, export hashes, manifest hashes/keys, active pointer hash, selected registry hashes and workflow identity. It excludes product/bottle identity, prices, quantities, raw URLs/query strings, alerts, members, notes, raw payloads and credentials. Product-shaped drop `name`/`id` fields cannot become premise identity. Stale or disabled exact-store inventory remains an earlier inventory connection even when its current alert flag is false. The one-hour flag is conservative raw classification, not customer-feed eligibility or verified physical stock.

## Bounded history and alias reconciliation

The window is the active snapshot, `pointer.previous`, and additional unique snapshot IDs from at most the first 20 retained immutable activation events, capped at six snapshots total. Pointer-event keys use reverse timestamps; the provider's first list page is used without pagination. The artifact records selection limits, missing snapshots and each complete manifest's generation time. Even a fully read selected window always sets `exhaustiveHistoricalAbsenceProven: false`: pruning, more events, older snapshots and unenumerated sources prevent a full historical census.

Each complete snapshot contributes all premise rows from its three public premise-bearing exports, including stale/history observations. Repository `engine/data/store-universe/[A-Z][A-Z].json` rows and file hashes are included as a separate directory layer. Address normalization supports comparison while preserving original spelling and unit numbers; names, source/store identities and original addresses remain available for manual alias reconciliation. Directory presence is not an inventory connection. Distinct source IDs or spelling changes are not automatically distinct physical stores.

The encrypted broad snapshot excludes independent scheduler overlays. The current capture tool also requests a separately timestamped, sanitized independent-source supplement described below. Verified-retailer submissions, other embedded source registries and retained data outside the window remain excluded. The existing local diagnostics artifact lacks the canonical premise-bearing exports and cannot fill that gap. Before counting a candidate as new, the lead must reconcile all captured public inputs and relevant source configurations, investigate address/name aliases and older positive matches, and record unresolved gaps. A missing match is provisional, never a new-store proof. If retained history exceeds the window, any follow-up must explicitly enumerate the remaining retained manifests in bounded reviewed batches and retain the completeness ledger; do not silently widen this run or infer absence from unavailable history.

## Execution and cost limits

The new `.github/workflows/coverage-premises-baseline.yml` is manual-only preparation for a future reviewed PR and default-branch registration. Both the job and credentialed CLI require `refs/heads/main`; arbitrary branch capture is blocked. It has not been dispatched or installed, and the actual baseline remains pending a reviewed release and authorized capture. No branch workaround or shared workflow change is prepared. Credentials are exposed only to the capture step in GitHub Actions. Never extract the Blob/encryption keys to a workstation.

The prepared workflow has read-only repository permissions, one non-cancelling concurrency group, an eight-minute job timeout, Node 24, `npm ci --ignore-scripts`, offline tests before credentials, and only the sanitized JSON artifact uploaded for 30 days. There is no schedule, collector, monitor/rescue, publication or dispatch command. Blob's existing credential has broader provider capability, but this script imports only the read-only adapter/list operation and makes no remote mutation call. Each projected observation carries its snapshot identity and observation time when available; directory metadata cannot become an inventory connection even if it carries inventory-like flags.

Capture limits are six snapshots, 20 activation-event rows, 48 manifest/encrypted-export reads, 100,000 projected rows, 12 MiB per manifest/encrypted object and 64 MiB aggregate manifest/encrypted bytes. Event reads are separately capped at 20 and 16 KiB each; there are two active-pointer reads and two public health reads. SDK metadata lookups add requests beyond those object-read counts. Operations have 15-second promise deadlines and the job stops at eight minutes. The existing adapter buffers responses: byte checks occur after read and a promise deadline cannot cancel that adapter's in-flight fetch. These are validation/job bounds, not a streaming network-byte guarantee; there are no retries or pagination. Exhaustion can yield a gap for history, never an absence claim.

## Independent source supplement added in the shared foundation

The capture step now uses the existing GitHub-held `SOURCE_SCHEDULER_SECRET` to request the exact authenticated `read=1&premises=1` scheduler endpoint. That query cannot invoke collection, monitor heartbeats, trace writes or recovery. The endpoint executes one fixed SELECT over current poll projections/last-positive episode seeds and retained lane subjects/opportunities, projecting public premises fields server-side before returning data. Customer tables, product/bottle data, prices, raw source payloads and URL query strings are excluded. All authorized existing read roles use the same bounded projection; missing authorization, extra/duplicate parameters and mixed monitor queries are denied.

The supplement has its own statement time, source generation/revision and policy identity, public registry/head/premises hashes, current/stale/negative/retained/orphan flags and explicit gaps. Its exact release commit must match the surrounding broad capture's verified release. It is not a transaction across Blob and SQL: pointer/live identity are rechecked around the separately timestamped read. Missing production supplement, changed commit, read error or excessive response fails the credentialed capture; offline tests without the callback explicitly report it missing.

Bounds are 100 heads per storage family, 10,000 public observations and 2 MiB response. Limits fail closed rather than truncating into an absence claim. SQL uses one MVCC statement, but its result and SDK byte guards apply after retrieval; the 15-second caller deadline and Vercel/job limits are not a database streaming or statement-timeout guarantee. Replaced poll projections and pruned lane history remain unavailable; `historicalAbsenceProven` and `retainedHistoryComplete` are always false. Current source classification is not normal customer eligibility or physical shelf proof. Known incomplete identities and undeclared sources remain gaps.

The focused SQL test executes the real statement against the existing schemas in local PGlite; route tests execute the saved authenticated handler and verify that rejected and successful premise reads never call collectors or monitors. The snapshot tests cover exact independent-release binding and missing/error cases. No database/encryption keys are copied to a workstation, and only the sanitized combined artifact is uploaded.

# Audited isolated canary health

The latest accepted production baseline keeps New Mexico's sole `inventory_confirmation_overdue` warning. A coherent canary replaces its complete state partition and removes the expired historical sibling, but the previous builder retained that warning. Production correctly rejects preview rows as an exception to production degradation, so carrying the obsolete warning into an isolated preview would suppress otherwise valid canary rows.

Only an existing active-four renewal with complete raw source evidence can retire that candidate state's inherited, non-stale, sole overdue warning. The CLI re-runs the existing family preparer against the exact extracted source report, bodies, receipts, full Bible and verified workflow provenance. The prepared candidate must match its serialized input. A process-private WeakMap token then binds the candidate and exact partition/location identities. Serialized tokens, marker-only input, missing/malformed bodies, stale clocks and altered candidates cannot regenerate that authority.

The derived canary stats remove only that state's obsolete entry from `refreshHealth.degradedStates` and update that list's count. Original production health records, other health counters and every sibling warning remain unchanged. An explicit `canaryDerivedStateReplacements` receipt retains the retired warning, source head/run/ZIP/cohort and body/payload digests, original observation window, exact row digest and current/known store IDs. No production state-health file, source clock, notification permission or production preview-row rejection changes.

Complete audited zero remains zero and retains known premises without stock. Denied, unresolved, stale-useful, quarantined, unknown, malformed or mixed warnings remain in force. Inactive candidate states cannot obtain active-renewal attestation. This does not introduce a new source or promotion protocol.

Programmatic owned-preview unions must call `attestActiveRenewalCanaryHealth` with the exact selected prepared candidate and original raw inputs, or `attestActiveRenewalCanaryHealthFromArtifact` with the original extracted artifact/provenance, then pass the returned opaque `candidateHealthAttestation` into `buildStateCanaryPreview`. Each state needs its own token. Existing exact partition and whole-union digest checks remain mandatory. A serialized token or a candidate drop array alone grants no health authority.

Targeted tests cover positive and complete-zero replacements, coherent multi-state unions, serialized CLI regeneration, missing bodies, candidate mutations and preservation of all other health. All nine issuer closures bind the shared attester, both existing preparers and the regression. No retailer HTTP or fresh qualification observation occurred while preparing this correction; the earlier v3 producer remains immutable and requires a new frozen ref.

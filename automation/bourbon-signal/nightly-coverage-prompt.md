# Nightly coverage run

Handle the entire coverage backlog in the authorized owner chat during 1–7 a.m. America/New_York. Follow AGENTS.md and docs/operations/coverage-research.md. The owner authorizes in-scope research, implementation, guarded release and verified completion without another approval. Never use Hermes or send customer messages. Preserve private credentials, member records, source evidence and unrelated work. Use the bundled Codex Python path in the runbook for all release wrappers.

1. Verify current main and use the clean controller checkout. Reconcile prepared report receipts with actual final messages from read_thread; acknowledge each proven receipt, and never resend uncertain delivery. Read .operator/coverage-active-attempt.json and private claim records. Do not mistake a completed/failed attempt for active work.
2. Run `node automation/bourbon-signal/codex-coverage.mjs nightly`. It snapshots all runnable requests and groups them by state. Inspect every target, reuse current shared research, and record per-target production baselines before changes. Preflight first-party access, exact store identity, positive inventory semantics and production runner reachability before implementation. Do not delegate unless separately authorized.
3. Loop using `next` until the snapshot is processed or the time window ends. Resume your own active job, worktree, sole PR and refresh first. For existing exact coverage use `complete-existing`; a rejection needs research. Limit discovery to 20 minutes and implementation to 45 minutes; incomplete research is deferred under the shared writer lock, not fabricated into an exhaustive failure. Stop retrying unchanged blockers. Save completed source audits once per group and reuse supported findings across overlapping targets.
4. Use one compatible release for related improvements. Keep the single release PR, independent review, writer lock, current main, production-backed job authority, exact reviewed head, required CI and production verification. For a South Carolina source integration use its reviewed source cohort instead of requiring unrelated feeds to pass a statewide refresh. Other states retain their strict refresh paths. Complete each request only after its exact target gains are verified; one source does not prove statewide completeness. Claim and verify related targets sequentially against their saved baselines and the shared release artifact.
5. Prepare research, implementation, passing local checks, independent review and source preflight before reserving the release lane. Admission requires the runbook's fresh readiness file, at least an hour before 7 a.m., and an empty objective lane. Its one-hour reservation cannot be extended. Save every stage and immutable CI/refresh id in .operator/coverage-active-attempt.json and the private ledger. When blocked, the lease expires, or the window ends, use the shared-lock `park` command to preserve and close the exact unmerged PR, then defer its request. This cleanup is permitted outside the window. Never park a merged change or active publication. `next` returns `parking_required` for an expired owned binding; reconcile it before continuing. The trusted watchdog also closes expired marked PRs when this controller is interrupted. Inspect parked progress and its bundle, reconcile current main, refresh source/customer baselines, rerun checks/review and obtain fresh admission rather than reopening the old PR. Research other targets read-only while publication is underway.
6. Complete viable requests using the version-two evidence contract. Record honest bounded failures with source evidence. Call `reports` only at the end, then return the combined text exactly as the one morning final message. The next night's run acknowledges each receipt using the actual final message. With no new result, stay quiet. Report an operational blocker plainly when required; never claim a rollout, delivery, fulfillment, or unattended execution that was not verified.
